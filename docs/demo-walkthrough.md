# Demo walkthrough

A short demo works best when it follows one real, public job listing and a sample resume that contains no private information.

## Two-minute path

1. **Start with the problem.** “Students often have to compare job descriptions, tailor materials, and track applications in separate places. AutoApply puts that workflow together while keeping the candidate in control.”
2. **Show the role.** In Career Studio, search a role and location. Open one result and show its source link and full description.
3. **Show the evidence check.** Upload a text-based sample PDF and point out that the keyword coverage is an estimate. Show matched and missing terms; explain that missing skills are never invented.
4. **Generate the packet.** Accept the AI data-use notice and create the resume and cover-letter drafts. Open the match matrix, then download both PDFs.
5. **Close the loop.** Save the role to the tracker and open the employer's application page. Say clearly that AutoApply prepares materials; the candidate reviews and submits them.

## Optional extra, if time allows

Show the voice coach: record a short, non-sensitive answer, read the separate consent, and explicitly transcribe it. Review the transcript before sending it to the coach.

## Demo reliability checklist

- Test the exact presentation computer, browser, provider key, OAuth account, and microphone permission ahead of time.
- Keep a synthetic sample resume and a known job listing ready. Do not place a real person's resume or API key in a public repository or recording.
- Search live during the demo when the source boards respond. If they do not, use a clearly labeled recording or sample; never describe cached sample data as live.
- Have a previously generated sample packet ready as a clearly labeled fallback in case a provider is unavailable.
- Do not promise a perfect ATS score, guaranteed interviews, or automatic application submission.
